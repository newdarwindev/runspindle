# Maintained workflow evidence v1

`runspindle.maintained-evidence.v1` extends the reviewed integration contract with
bounded native library interfaces. Runtime v1, integration v1 and fixture v1
retain their existing meanings. The [descriptor](../contracts/maintained-evidence-v1.json)
lists required bindings and limits. Components reject an unsupported version
before storage or adapter calls. This mapping does not establish JSON wire
interoperability or qualify an unimplemented producer.

Refinery owns immutable lineage snapshots, collection evidence, authenticated
feedback observations, quarantine and deterministic family locks. Collection
verification grants neither provider transmission nor task execution. Locked
experiments bind exact baseline, candidate, dataset, split and effective
configuration bytes. Shared budget reservations and attempt identities commit
before invocation; an interrupted pending attempt remains unknown, retains its
reservation and blocks automatic replay. Completed experiment evidence is
immutable. Scripted and local DSPy lanes report synthetic usage and narrow exact
match scores; neither measures provider quality or monetary cost.

Approval verification defaults to deny and binds exact candidate/evaluation/
policy bytes and environment. A generation compare-and-swap owns each promotion
or rollback. Activation intent commits before loading. Registry intent is not
proof of serving: independent adapter readback must report both activation ID
and the digest loaded from verified bytes. Missing or conflicting readback stays
unknown and fences later activations. A positively rejected atomic load retains
the prior candidate. Rollback requires available, compatible approved bytes;
absent history fails closed. Outputs carry the digest actually used to serve
them, including while registry acknowledgement is missing.

Platform telemetry must distinguish queued, exported, persisted, rejected, lost
and unknown. Only backend readback of the same correlated envelope establishes
persistence. Whole-envelope privacy includes resource/scope schema URLs, names,
metadata, errors and paths. Unsupported privacy enforcement blocks the path;
synthetic OTLP qualification does not qualify native telemetry or console views.
Use standard Collector components and supported backend APIs, not a replacement
receiver or uploader. Dependency preparation is separate from isolated execution.

Development bundles identify seven component pins, source composition, licenses,
dependencies, toolchains and supported target. Installation and recovery occur
only in disposable targets with independent installed-byte checks. Missing
product adapters are explicit unsupported capabilities. No installed-service or
full-product release claim follows from installing a development bundle.

All stores use bounded inputs, explicit schema versions and retained immutable
identities; no implicit eviction authorizes a duplicate effect. SQLite evidence
qualifies process interruption in a disposable local filesystem, not power loss,
hostile database modification, backup, production retention or schema upgrades.
Components own their stores; composition reads independent ledgers and never
writes another component's state. Unavailable checks remain blocked/not-run.
